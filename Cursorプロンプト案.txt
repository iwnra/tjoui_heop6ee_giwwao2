# 役割と目的
あなたは経験豊富なシステムエンジニアおよびQAエンジニアです。
プロジェクトの運用ルールに従い、結合テスト（PT）の「PT仕様書」および「テストデータ投入用SQLスクリプト」を作成してください。

# 前提条件・制約事項
1. **仕様書の見本とテンプレート**
   - 添付（または提供）する「PT仕様書の見本」の記述レベル・観点・粒度を必ず参考にしてください。
   - 成果物は、添付（または提供）する「PT仕様書テンプレート」のフォーマットをそのままコピーして作成してください。

2. **データベース（DB）接続とマスタデータ**
   - DB構造や型の確認は、プロジェクト内で設定されている既存のDB接続設定を使用して行なってください。
   - テストケースは、**すでにDBのマスタテーブルに登録されているデータを使用する前提**で作成してください。
   - **【厳禁】** マスタデータ（`M_`で始まるテーブル等）の変更・追加・削除（UPDATE/INSERT/DELETE）を行うSQLやテストケースは作成しないでください。

# タスク1：PT仕様書の作成
添付のテンプレート構造を維持しつつ、対象機能の処理フローやエッジケースを網羅したテストケースを作成してください。
- 期待値は「画面挙動」「DBの更新結果」「出力ログ/ファイル」など具体的に記載すること。
- マスタデータを前提とする事前条件を明記すること。

# タスク2：テストデータ用SQLファイルの作成（.sql）
PT仕様書のテストケースを実行するために必要なトランザクションデータ等のテストデータを準備・管理するためのSQLを作成してください。
SQLは以下の3つのセクションに分けて出力（または別ファイル化）してください。

1. **登録用SQL（INSERT）**
   - テストに必要なトランザクションデータ等の作成用。
   - テーブルの制約（NOT NULL、外来キー等）を満たした正しい構文とすること。
2. **登録確認用SQL（SELECT）**
   - 登録されたデータが正しくセットされているかを確認するための検索クエリ。
3. **削除用SQL（DELETE）**
   - テスト実施後に環境を元の状態に戻す（クリーンアップ）ためのクエリ。
   - 登録したデータのみをピンポイントで削除できるよう、主キー指定や実行順序（外部キー制約の考慮）を厳格に行うこと。

# 成果物の出力形式
1. **PT仕様書**（指定テンプレートの形式）
2. **SQLファイル**（ファイル名例: `test_data_[機能名].sql`）
   - コメントで「どのテストケース用のデータか」が明確にわかるように記述すること。

# データベース構造の参照
- テーブル定義やカラム構造、型、制約は `@schema.sql` を参照してください。
- レコードの実際のデータ傾向や連携（繋がり）を確認する場合は、プロジェクトの接続設定を使用し、DBからサンプルデータを数件参照してください。


mysqldump -u [ユーザー名] -p --no-data [データベース名] > schema.sql

--no-data（または -d）：データを出力せず、CREATE TABLE などの DDL のみを出力します。
--routines や --triggers を追加すると、ストアドプロシージャやトリガーも一緒に出力できます。
